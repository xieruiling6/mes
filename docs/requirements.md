## 1. 文档目的

本文定义工擎 MES 第一版的目标用户、业务范围、角色权限、核心流程、功能模块、页面、业务规则、开发顺序和验收边界，作为后续数据库设计、接口设计、开发与测试的共同依据。本文是需求文档，不包含具体代码或最终数据库 DDL。

## 2. 项目概述

工擎 MES 面向中小型制造企业，围绕“生产订单到生产执行再到报工统计”管理生产过程。系统帮助企业把待生产数量分解为计划和工单，记录现场产出，并能查询订单、计划和工单的执行进度。

### 2.1 第一版目标

1. 维护参与生产管理的产品基础资料。
2. 将生产订单转化为生产计划，并从每份计划创建一张对应生产工单。
3. 按生产工单记录合格数量和报废数量，形成可追溯的报工记录。
4. 根据有效报工汇总订单、计划、工单的完成数量和进度。
5. 提供生产统计页面，支持管理人员查看阶段性产量和完成情况。
6. 提供登录、角色权限、基础操作校验，使主要业务数据只能由授权用户维护。

### 2.2 目标用户与业务场景

| 用户 | 主要场景 | 主要诉求 |
| --- | --- | --- |
| 企业负责人/生产经理 | 查看订单执行、计划达成、产量和报废概况 | 快速识别逾期、未开工、进度落后的任务 |
| 计划员 | 根据已确认生产订单安排生产计划，并从计划创建工单 | 控制计划数量与订单数量一致，跟踪计划及工单状态 |
| 车间主管 | 查看待执行和进行中的工单，跟进生产任务 | 了解工单进度，及时发现停滞或数量异常 |
| 操作员/报工员 | 查询分配给车间的工单并提交生产报工 | 准确记录产出、报废数量和生产时间 |
| 系统管理员 | 维护账号、角色权限和产品资料 | 控制系统访问和基础数据质量 |

第一版按单工厂、单企业内部使用进行设计，不提供多租户、跨组织协同或复杂组织架构能力。

### 2.3 范围与假设

本需求采用以下已确认的第一版业务模型：

- 一个生产订单只包含一个产品和一个订单数量。
- 一个生产订单对应一份生产计划。
- 一份生产计划最多创建一张生产工单，工单数量等于计划数量。
- 每个生产工单针对该订单的同一种产品，记录独立的计划数量和执行状态。
- 工单直接报工，不拆分工艺路线或多道工序。
- 有效报工保存后直接计入执行进度；第一版不设置报工审核流。
- 产品、订单、计划、工单和报工数据保存在本企业系统内；第一版不对接 ERP、设备或自动采集系统。

上述“报工保存后计入进度”是为控制第一版复杂度采用的业务假设，后续若需要班组长审核，可在报工记录上增加审核状态和审核流程。

## 3. 角色与权限

系统采用基于角色的访问控制（RBAC）。用户账号关联一个或多个角色，角色授予模块操作权限。后端接口必须执行权限校验，前端菜单和按钮显隐仅用于改善操作体验，不能代替后端校验。

### 3.1 角色定义

| 角色 | 定位 |
| --- | --- |
| 系统管理员 | 负责用户、角色和系统基础配置；可访问全部业务模块 |
| 生产经理 | 负责订单及生产总体跟踪，可维护产品、生产订单，查看计划、工单、报工和统计 |
| 计划员 | 负责生产计划编制、发布及工单创建 |
| 车间主管 | 负责查看工单执行情况，可查看报工明细和进度 |
| 操作员 | 负责查看可执行工单并提交、查询本人报工记录 |

第一版可由系统初始化时创建以上角色。系统管理员可以给用户分配角色，但不实现自定义权限表达式或复杂的数据范围规则。

### 3.2 权限矩阵

“查看”包括列表、详情及必要的导出前查询；“管理”包括新增、修改、发布或取消等该模块规则允许的操作。

| 模块/操作 | 管理员 | 生产经理 | 计划员 | 车间主管 | 操作员 |
| --- | --- | --- | --- | --- | --- |
| 首页/生产看板 | 查看 | 查看 | 查看 | 查看 | 查看个人可执行工单 |
| 产品资料 | 管理 | 管理 | 查看 | 查看 | 查看 |
| 生产订单 | 管理 | 管理 | 查看 | 查看 | 无 |
| 生产计划 | 管理 | 查看 | 管理 | 查看 | 无 |
| 生产工单 | 管理 | 查看 | 管理 | 查看 | 查看可执行工单 |
| 生产报工 | 查看/作废 | 查看 | 查看 | 查看 | 新增、查看本人记录 |
| 生产统计 | 查看 | 查看 | 查看 | 查看 | 无 |
| 用户与角色 | 管理 | 无 | 无 | 无 | 无 |

实现时应进一步明确每个按钮对应的权限标识。管理员的报工作废权限仅用于错误数据更正；作废需要填写原因，作废记录保留审计信息且不再计入进度。生产经理第一版不作废报工，避免与生产数据更正责任混淆。操作员只能对自己有权执行的工单报工；若第一版尚无班组/工位分配，操作员可查看所有“进行中”工单，此范围在验收部署时作为单企业简化规则。

## 4. 核心业务对象及关系

| 对象 | 说明 | 核心关系 |
| --- | --- | --- |
| 用户/角色/权限 | 登录身份与功能授权 | 用户可关联角色，角色可授予多个权限 |
| 产品 | 可被生产的成品基础资料 | 一个产品可被多个生产订单引用 |
| 生产订单 | 客户/内部需求对应的待生产任务 | 一个订单引用一个产品，并对应一份计划 |
| 生产计划 | 将订单需求安排到生产执行的任务 | 一份计划属于一个订单，最多创建一张工单 |
| 生产工单 | 车间可执行的生产任务 | 一个工单属于一份计划，包含计划数量和执行状态 |
| 生产报工 | 对某工单某时段的实际产出记录 | 一个工单可有多条报工记录；报工由用户提交 |

逻辑关系：`产品 1 - N 生产订单；生产订单 1 - 1 生产计划；生产计划 1 - N 生产工单；生产工单 1 - N 生产报工`。

第一版建议采用软删除/停用管理基础资料。已有业务引用的产品不得物理删除；已进入生产的订单、计划和工单不得直接删除。单据终止通过状态和操作记录表达。

## 5. 核心业务流程

### 5.1 主生产流程

1. 管理员或生产经理维护启用状态的产品。
2. 生产经理创建生产订单，选择产品，填写订单数量、要求完成日期和备注。
3. 生产经理确认订单。确认后订单作为生产计划来源；确认订单不允许直接物理删除。
4. 计划员为已确认订单创建唯一生产计划，填写计划日期及计划数量。
5. 计划员创建并发布生产计划，之后从计划创建一张工单；工单数量、日期均由服务端从计划读取。
6. 主管下发工单并开始生产，工单可供车间执行。
7. 主管下发工单并开始生产。操作员选择生产中的工单，填写报工日期、合格数量、报废数量及备注并提交。
8. 系统即时更新工单的累计合格数、累计报废数、完成数及进度，并向计划和订单汇总。
9. 工单有效报工总量恰好达到计划量后可完成；工单完成后计划和订单同步完成，工单不可恢复。
10. 生产经理、计划员和车间主管通过看板、列表和统计页面跟踪执行结果。

### 5.2 订单与计划状态

| 对象 | 状态 | 允许的主要流转 |
| --- | --- | --- |
| 生产订单 | 草稿 | 创建后可编辑；确认后进入“已确认” |
| 生产订单 | 已确认 | 创建计划；在无已发布计划且无报工时可取消 |
| 生产订单 | 生产中 | 关联工单开始生产时进入；工单完成后订单同步完成 |
| 生产订单 | 已完成 | 所有关联工单均完成且有效完成数达到订单数量 |
| 生产订单 | 已取消 | 终态；保留单据和操作记录 |
| 生产计划 | 草稿 | 可编辑计划数量、日期；发布后不可直接编辑 |
| 生产计划 | 已发布 | 可创建一张工单；关联工单开工后进入生产中 |
| 生产计划 | 生产中 | 关联工单已开始生产且计划未完成 |
| 生产计划 | 已完成 | 关联工单完成且累计有效报工量达到计划数量 |
| 生产计划 | 已取消 | 仅可在无有效报工时取消，保留记录 |

### 5.3 工单状态

| 状态 | 含义和流转 |
| --- | --- |
| 待下发 | 工单已创建，等待下发 |
| 已下发 | 工单已下发，等待开始生产 |
| 生产中 | 正在生产，可暂停或在数量达标后完成 |
| 已暂停 | 暂停生产，可恢复 |
| 已完成 | 有效报工总量达到工单计划量；不可恢复 |
| 已取消 | 未开始执行的工单因订单/计划取消而终止；不可恢复 |

第一版不设置返工、工序转移、插单、拆单历史版本或强制完工等流程。已创建工单的计划数量和日期不可由客户端修改。

### 5.4 报工与数量口径

- 每条报工记录包含工单、报工人、报工日期、合格数量、报废数量、备注、创建时间和记录状态。
- 合格数量、报废数量均为非负整数；单次报工数量（合格数 + 报废数）必须大于 0。
- 工单累计完成数 = 有效报工的合格数量 + 有效报工的报废数量。
- 工单剩余数 = max(工单计划数 - 工单累计完成数, 0)。
- 工单完成率 = min(工单累计完成数 / 工单计划数, 100%)；报废量计入已处理数量但不计为合格产量。
- 计划及订单的合格产量、报废量分别汇总其下所有有效报工；完成进度以合格量 + 报废量为分子。
- 为防止超报，提交报工时必须在事务内校验累计完成数加本次数量不超过工单计划数。
- 作废报工需有权限且必须填写原因；作废后不计入各层汇总，记录和作废人、时间、原因保留。
- 报工使用服务端身份确定报工人，不能信任前端传入的用户 ID。

## 6. 功能模块、依赖与页面需求

### 6.1 模块依赖

| 模块 | 依赖 | 说明 |
| --- | --- | --- |
| 登录与权限 | 用户、角色、权限数据 | 业务模块均依赖身份认证与授权 |
| 产品管理 | 登录与权限 | 订单创建时选择启用产品 |
| 生产订单 | 产品管理、权限 | 订单为计划的来源，引用产品 |
| 生产计划 | 生产订单、权限 | 一个已确认订单对应一个计划；计划最多一张工单 |
| 生产工单 | 生产计划、产品信息、权限 | 由计划分解创建并承接执行 |
| 生产报工 | 生产工单、登录用户、权限 | 产生实际数量，是进度和统计数据源 |
| 进度看板 | 订单、计划、工单、报工 | 展示汇总和异常清单，不直接改业务数量 |
| 生产统计 | 报工及单据数据 | 对有效报工和计划数量进行聚合 |

### 6.2 登录与系统管理

**主要页面**：登录页；用户列表/详情；角色列表/权限配置；个人资料与修改密码。

**第一版功能**：账号密码登录、退出、用户启用/停用、用户角色分配、角色菜单及操作权限配置、修改密码。系统不开放自助注册。

**业务规则**：停用用户不能登录；停用用户的历史报工记录保留；不得停用当前唯一可用系统管理员；密码不明文保存。页面路由和后端接口均应做未登录、无权限处理。

### 6.3 产品管理

**主要页面**：产品列表、产品新增/编辑表单、产品详情。

**核心字段建议**：产品编码、产品名称、规格型号、计量单位、备注、启用状态、创建/更新时间。

**业务规则**：产品编码必填且唯一；产品名称和计量单位必填；被订单引用的产品不可物理删除；停用产品不可用于新订单，但历史订单正常展示。

### 6.4 生产订单

**主要页面**：订单列表、创建/编辑订单页、订单详情页。详情展示产品、订单数量、交期、状态、关联计划、工单进度和报工汇总。

**核心字段建议**：订单编号、产品、订单数量、要求完成日期、备注、状态、创建人及时间。

**业务规则**：订单编号唯一；数量为正整数；交期不得早于创建当天（如业务确需补录，可由管理员处理）；仅启用产品可用于新订单；草稿可编辑，确认后受状态规则约束；订单只能创建一份计划；取消前必须确认没有已发布执行任务和有效报工。

### 6.5 生产计划

**主要页面**：计划列表、计划创建/编辑页、计划详情。计划详情显示订单需求量、计划量及关联工单状态。

**核心字段建议**：计划编号、关联订单、计划数量、计划开始/结束日期、状态、备注、创建/发布时间。

**业务规则**：同一订单最多一份计划；计划数量须等于订单数量；计划结束日期不早于开始日期且不晚于订单交期（如订单交期存在）；计划发布后可创建一张工单，工单数量和日期从计划读取且等于计划数量和日期；发布后不可直接修改关键数量或日期。

### 6.6 生产工单

**主要页面**：工单列表、工单详情及计划选择创建入口。列表支持按编号、产品、计划、状态、日期筛选；详情显示计划数量、累计合格数、累计报废数、剩余数、进度和报工记录。

**核心字段建议**：工单编号、计划、订单、产品、计划数量、计划开始/结束日期、状态、备注。

**业务规则**：一个计划最多创建一张工单，工单编号唯一，产品由来源订单确定，计划数量和日期由已发布计划确定；状态按待下发、已下发、生产中、已暂停、已完成流转；完成或取消的工单不得恢复；完成数以有效报工记录为准，完成前必须恰好达到工单计划数量。

### 6.7 生产报工

**主要页面**：我的可报工工单/工单选择页、报工录入页、报工记录列表、报工记录详情。主管及以上可按工单、报工人、日期查看记录；操作员默认查看本人记录。

**核心字段建议**：报工编号、工单、报工人、报工日期、合格数量、报废数量、备注、记录状态及作废信息。

**业务规则**：只允许对生产中的工单报工；采用前述数量口径与超报校验；报工保存后即时计入进度；记录不允许静默覆盖或物理删除；更正通过授权作废并保留原因，之后可按正确数据重新报工。

### 6.8 进度看板

**主要页面**：生产总览页；订单进度列表；逾期/未开工/进行中工单列表；订单或计划进度详情。

**第一版展示**：订单总数、生产中订单数、逾期订单数、计划数量、累计合格量、累计报废量；订单和计划完成率；按状态的工单数；待处理与逾期工单清单。

**业务规则**：看板数值与单据详情使用同一计算口径；统计只包括未作废报工；筛选条件须明确统计日期范围及状态范围。看板以只读汇总为主，业务操作回到对应单据页面。

### 6.9 生产统计

**主要页面**：生产日报/区间统计页、产品产量统计页、订单完成情况页。

**第一版统计维度**：按日期、产品、订单、工单汇总合格量和报废量；按订单或计划展示计划量、累计完成量和完成率。提供日期范围及产品/状态筛选，支持 CSV/Excel 导出可作为首版可选项，若时间紧张可留在后续版本。

**业务规则**：报工日统计使用报工日期而非创建日期；产量与报废量分开展示；作废记录不参与汇总；同一统计页面应标明其统计范围。

## 7. 第一版范围与后续扩展

### 7.1 第一版必须实现（MVP）

1. 登录、退出、用户启停、角色分配及后端权限校验。
2. 产品资料新增、编辑、查询和停用。
3. 生产订单新增、编辑、确认、取消、查询及详情。
4. 每个订单创建一份计划，计划发布后从该计划创建一张同数量工单。
5. 工单状态管理、列表筛选、详情和进度汇总。
6. 操作员按工单提交报工，记录合格/报废数量；完成数和超报校验正确。
7. 管理员作废错误报工并记录原因，作废数据不再进入进度/统计。
8. 订单、计划、工单状态和汇总数量随有效报工更新。
9. 基础生产看板和按日期/产品/订单的生产统计页面。
10. 统一异常响应、服务端参数校验、分页查询、基础操作日志和可复现的数据库初始化/部署说明。

### 7.2 后续版本

- 多产品订单、订单拆分/合并、订单变更审批及数量变更历史。
- 工艺路线、工序、工序流转、工序级工单和工序级报工。
- 报工班组长审核、返工、返修、质量检验、抽检及不良原因分析。
- BOM、原材料、仓库、领料、退料、库存和采购计划。
- 设备、工装、维护、停机原因、OEE 和设备数据采集。
- 多工厂、多车间、多班组、组织数据范围和跨租户隔离。
- ERP、WMS、PLM、条码/RFID、IoT 设备和自动化产线对接。
- 高级排产、产能日历、有限产能约束、甘特图和智能排程。
- 移动端、扫码报工、消息提醒、异常预警和多语言。
- 可配置报表、BI 分析、审计追踪扩展及复杂数据导出。

## 8. 非功能需求

### 8.1 技术基线

- 后端：Java 17、Spring Boot 3.x、Maven、MyBatis-Plus。
- 数据库：MySQL 8。
- 前端：Vue 3、Vite、Element Plus、Axios、Vue Router、ECharts。
- 版本管理：Git。数据库变更脚本随项目版本管理，避免仅依赖手工改库。

Spring Boot 3.x 与 Java 17 兼容；具体 Spring Boot 小版本及依赖版本应在创建项目时统一锁定，避免追随动态版本。

### 8.2 安全与数据完整性

- 密码需安全哈希存储，接口不得返回密码或凭据。
- 所有业务写接口校验身份、权限、单据状态和关联关系。
- 关键操作（确认、发布、取消、作废）需记录操作者、时间及必要原因。
- 订单编号、计划编号、工单编号、报工编号在系统范围内唯一。
- 对订单、计划、工单、报工的数量变化和状态流转使用事务，避免部分提交。
- 校验日期、正整数、数量分配、工单超报及并发报工冲突。
- 列表接口使用分页；敏感配置由环境变量提供，不提交真实凭据。

### 8.3 可用性、可维护性和可部署性

- 常用列表提供分页、关键字搜索、状态和日期筛选，详情页展示必要的关联单据。
- 表单明确必填项、数量范围和后端返回的业务错误，不依赖前端校验作为唯一防线。
- 前后端通过有版本管理的 REST API 协作，统一响应与错误码约定在技术设计阶段确定。
- 提供本地启动配置、MySQL 初始化/迁移方式、示例数据及部署步骤；不得要求依赖未说明的外部服务。
- 第一版面向小型团队内部使用，预期数据规模以数万级单据和报工记录为设计参考，性能指标在实现环境确定后压测并细化。

## 9. 开发顺序与交付阶段

| 阶段 | 工作内容 | 前置依赖 | 阶段验收 |
| --- | --- | --- | --- |
| 1. 需求与规则确认 | 固化数量口径、状态流转、角色、页面和边界 | 无 | 本文评审通过，关键流程无歧义 |
| 2. 技术骨架 | 建 Git 结构、Spring Boot/Vue 工程、配置、统一响应、跨域与启动说明 | 阶段 1 | 前后端可独立启动并连通健康检查 |
| 3. 数据库及权限基础 | 用户、角色、权限、登录、初始化数据、数据库迁移 | 阶段 2 | 能登录，接口按权限拒绝未授权访问 |
| 4. 产品与订单 | 产品维护；订单创建、确认、取消、查询 | 阶段 3 | 可从产品创建有效生产订单 |
| 5. 计划与工单 | 创建计划、发布、从计划创建工单、状态管理 | 阶段 4 | 一份计划最多一张同数量工单，非法状态操作被拒绝 |
| 6. 报工与进度 | 报工记录、超报并发保护、作废、数量汇总和状态更新 | 阶段 5 | 报工后订单/计划/工单数量与状态一致 |
| 7. 看板与统计 | 汇总接口、图表、筛选和可选导出 | 阶段 6 | 统计结果可与报工明细逐项核对 |
| 8. 测试与部署 | 关键业务测试、前后端联调、异常场景、部署和演示数据 | 阶段 7 | 按部署文档可重建环境并走通端到端生产流程 |

建议先完成一条纵向闭环（登录 -> 产品 -> 订单 -> 计划 -> 工单 -> 报工 -> 进度），再扩展统计与页面细节。数据库结构和状态枚举应在第 3 至第 5 阶段按已确认规则设计，避免前后端各自定义口径。

## 10. 难度评估与第一版控制策略

| 子域 | 难度 | 主要风险 | 第一版控制方式 |
| --- | --- | --- | --- |
| 登录与 RBAC | 中 | 权限只在前端隐藏、角色权限过于灵活 | 固定角色模板，后端统一校验 |
| 产品/订单 CRUD | 低 | 删除被引用数据、编号重复 | 唯一约束，引用后停用而非删除 |
| 计划与工单数量 | 低 | 工单数量与订单或计划不一致 | 计划量等于订单量；建单时从计划读取并由服务端校验 |
| 报工与进度 | 中高 | 并发超报、报废计数口径、重复提交 | 数据库事务与数量校验；报工记录可追溯 |
| 状态流转 | 中 | 前端绕过流程、非法状态切换 | 服务层集中定义允许的状态转换 |
| 看板和统计 | 中 | 汇总口径不一致、查询变慢 | 复用统一汇总口径；先做有限维度和日期范围 |
| 多工序排程/质量/库存 | 高 | 引入复杂实体、流程和跨模块事务 | 明确排除在 MVP 之外 |

最大的第一版技术风险是“计划/工单/报工累计数量在并发写入和单据变更时保持一致”。建议以报工明细为事实来源，写入时事务内校验工单剩余量，统计从有效报工汇总；若后续使用缓存汇总字段，应以明细可重算并有一致性校验为前提。

控制首版范围的原则：只做一种产品订单模型、一个计划、一计划一工单、工单级报工、固定角色和基础统计；不做物料、工序、质量、设备、库存和高级排产。

## 11. MES 与普通后台管理系统的区别

普通后台管理系统通常以资料维护、审批和查询为核心，主要处理相对静态的业务记录。MES 面向生产现场执行，其核心是把计划落实为可执行任务，持续收集生产实际，并及时反映任务完成状态。

工擎 MES 因此需要特别处理：

- **执行链路**：订单、计划、工单和报工具备明确的上下游关系，不是孤立 CRUD 页面。
- **状态约束**：单据状态决定后续操作；确认、发布、开始、完成和取消必须遵循合法转换。
- **实时数量**：报工记录持续改变工单、计划、订单进度，所有页面需要共享一致口径。
- **现场数据质量**：错报、重复报工、超报和作废必须可识别、受控且可追溯。
- **计划与实际对照**：既展示静态计划数量，也展示报工形成的实际产量和差异。
- **向现场扩展的基础**：后续可接工序、条码、设备、物料和质量，但第一版不应提前实现这些复杂能力。

所以即使第一版的页面包含不少常见管理表格，系统设计重点仍应放在生产关系、数量守恒、执行状态和现场报工可靠性上。

## 12. 验收标准

1. 用户能登录，未登录或权限不足的用户无法通过直接调用 API 执行受限操作。
2. 可创建并停用产品；已被订单引用的产品无法被物理删除。
3. 可创建单产品生产订单并确认；订单只能创建一份生产计划。
4. 每个已发布计划最多创建一张工单；重复创建、无效计划和不一致数量均由后端拒绝。
5. 可对生产中工单报工；单次数量非法或累计超出工单数量时服务端拒绝。
6. 有效报工保存后，工单、计划、订单的合格数、报废数、完成数、剩余数、完成率和状态按统一规则更新。
7. 无效权限不能作废报工；授权作废需填写原因，作废后统计和进度不再计入该条记录。
8. 已完成或已取消工单不能继续报工；已有报工的工单不能被直接删除。
9. 看板和统计可以按时间或产品筛选，合计值能与相同范围内的有效报工明细核对。
10. 按部署说明可在干净环境初始化 MySQL、启动前后端并演示完整业务闭环。

## 13. 术语

| 术语 | 定义 |
| --- | --- |
| 合格数量 | 本次报工中判定为合格的产品数量 |
| 报废数量 | 本次报工中判定为报废、不再计入合格产量的数量 |
| 完成数 | 合格数量与报废数量之和，表示已处理的生产数量 |
| 有效报工 | 未被授权作废且参与业务汇总的报工记录 |
| 工单 | 从生产计划创建并交给车间执行的生产任务 |
| 订单完成率 | 有效报工完成数除以订单数量，最高显示为 100% |
