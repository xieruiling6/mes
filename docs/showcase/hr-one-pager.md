# 工擎 MES｜制造执行系统（个人全栈项目）

> 一句话：给中小型工厂用的「从接单到完工」数字化系统。把车间里散落在 Excel、微信群和纸质流转单上的订单、排产、报工、质检、设备维修，收进一套有权限、能审计、算得准的系统里。

**技术栈**：Java 17 / Spring Boot 3.5 / MyBatis-Plus / MySQL 8 ｜ Vue 3 / Vite / Element Plus / ECharts
**角色**：〔独立完成／负责后端与数据库，前端协作——按实际情况二选一〕
**周期**：〔约 X 周，从需求文档写到部署验证〕

---

## 1. 这个系统解决什么问题

工厂里最常见的三个坑，需求文档里逐条对应了解决方式：

| 现场痛点 | 系统里的做法 |
| --- | --- |
| 报工靠纸质单，月底对不上账，还容易多报 | 报工只能对「生产中」的工单提交，服务端锁行汇总，超过计划量直接拒绝（不是前端弹窗提醒，是后端不认） |
| 一张订单排了几个计划、开几张工单，谁也说不清 | 一个订单最多一份计划、一份计划只能开一张等量工单，由数据库唯一约束兜底 |
| 出了问题查不到是谁改的、什么时候改的 | 24 类关键动作写操作日志，谁、什么时候、对哪张单据做了什么全程可查 |

## 2. 已实现的功能范围

一条完整业务链路，10 个模块全部打通，不是并列的增删改查：

```
产品/工序 → 生产订单（草稿→确认） → 生产计划（排期→发布）
        → 生产工单（下发→开工→暂停→完工） → 生产报工（提交/作废）
        → 质量检验（合格/不合格处置） → 设备管理（档案/维修）
        → 生产统计（日报、合格率、计划执行率）
```

外加：登录认证、角色权限（RBAC）、用户/角色/权限管理、个人设置、响应式移动端。

## 4. 三个可以展开讲的技术点

1. **并发报工不超报**：两个操作员同时报最后 100 件，数据库行锁 + 事务内汇总校验，只允许一笔成功，另一笔返回 409，不会出现「账上多出 100 件」。
2. **重复提交不重复记账**：每次报工带一个唯一请求键，网络重试或误点两次只记一笔。
3. **权限不靠前端隐藏**：菜单按权限过滤只是体验，真正的拦截在服务端——操作员直接调管理接口会拿到 403；停用用户立即无法登录；系统不允许停用最后一名管理员。
