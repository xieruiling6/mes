# 工擎 MES 使用手册

> 适用版本：第一版（单工厂、单产品订单、一计划一工单、工单级报工）
> 目标读者：系统管理员、生产经理、计划员、车间主管、操作员

## 1. 产品简介

工擎 MES 是面向中小型制造企业的制造执行系统，围绕“生产订单 → 生产计划 → 生产工单 → 报工 → 完工 → 统计”管理生产过程。

它主要解决四类问题：

1. **订单执行不透明**：订单、计划、工单、报工层层关联，进度可以追溯到每条有效报工。
2. **报工数量容易出错**：服务端校验合格数、报废数和累计完成数，防止超报。
3. **报工数据不可追溯**：报工不允许直接修改或删除，只能由有权限人员填写原因后作废，再重新报工。
4. **统计口径不统一**：看板、订单详情、工单详情和统计报表使用同一套有效报工口径。

第一版不包含：多工厂/多租户、BOM 与库存、工艺路线执行、设备数据采集、报工审核流、ERP 对接。

## 2. 角色与权限

系统预置 5 个角色。管理员可以在“系统管理 → 角色与权限”中调整权限，但建议保持职责分离。

| 角色 | 适合人员 | 主要权限 |
| --- | --- | --- |
| 系统管理员 ADMIN | IT/系统负责人 | 全部业务权限；用户、角色、权限管理；报工作废 |
| 生产经理 PRODUCTION_MANAGER | 生产负责人 | 产品、工序、订单管理；质量、设备管理；查看计划、工单、报工、统计 |
| 计划员 PLANNER | 计划/生管 | 生产计划和工单编制、发布、取消；查看产品、订单、报工、统计 |
| 车间主管 WORKSHOP_SUPERVISOR | 车间管理 | 查看产品、工序、订单、计划、工单、报工、质量、设备、统计，只读跟踪 |
| 操作员 OPERATOR | 一线报工人员 | 查看工单；提交报工；查看本人报工记录 |

权限规则：

- 前端菜单和按钮会根据权限隐藏，但**后端接口始终重新校验权限**。
- 操作员默认只能查看本人报工；主管及以上可查看全部报工。
- 只有拥有 `report:void` 权限的角色才能作废报工。
- 停用用户不能登录，历史报工和操作记录保留。
- 系统必须保留至少一名启用状态的管理员，`ADMIN` 角色必须保留用户和角色管理权限。

## 3. 首次部署与登录

### 3.1 环境要求

- JDK 17
- Maven 3.9+
- Node.js 22+ 与 npm
- MySQL 8

### 3.2 初始化数据库

在项目根目录执行：

```bash
mysql -h 127.0.0.1 -u root -p < docs/sql/init.sql
```

`docs/sql/init.sql` 会创建 `gongqing_mes` 数据库、业务表、5 个预置角色和 29 个权限。

### 3.3 配置环境变量

复制 `.env.example` 为 `.env`，按实际环境填写数据库连接，然后导出：

```bash
set -a
source .env
set +a
```

至少确认：

```bash
DB_URL='jdbc:mysql://localhost:3306/gongqing_mes?useUnicode=true&characterEncoding=utf8&serverTimezone=UTC&useSSL=false&allowPublicKeyRetrieval=true'
DB_USERNAME=root
DB_PASSWORD='你的数据库密码'
```

### 3.4 创建首个管理员

只在数据库中没有用户时执行一次：

```bash
cd backend
export BOOTSTRAP_ADMIN_USERNAME=admin
export BOOTSTRAP_ADMIN_PASSWORD='至少12位的强密码'
mvn spring-boot:run
```

启动后访问 `http://localhost:8080/api/health`，返回 `status: UP` 表示后端启动成功。系统检测到已有用户后会自动跳过 bootstrap，不会覆盖已有管理员。

### 3.5 启动前端

```bash
cd frontend
npm install
npm run dev
```

浏览器打开 `http://localhost:5173`，使用 bootstrap 创建的管理员登录。生产环境应先执行 `npm run build`，再由 Nginx 等反向代理托管 `frontend/dist`，并将 `/api` 转发到后端。

### 3.6 首次登录后的配置顺序

1. 进入“系统管理 → 用户与角色”，创建用户并分配角色。
2. 进入“产品管理”，维护产品编码、名称、规格、单位。
3. 如需维护工序主数据，进入“工序管理”。
4. 进入“生产订单”，创建并确认第一张订单。
5. 按下面的标准流程执行。

## 5. 标准业务流程

以“订单 100 台”为例：

| 步骤 | 页面 | 操作 | 结果 |
| --- | --- | --- | --- |
| 1 | 产品管理 | 新增产品，填写编码、名称、单位 | 产品状态为启用 |
| 2 | 生产订单 | 新建订单，数量 100，填写交期，保存 | 订单为草稿 |
| 3 | 生产订单 | 点击“确认” | 订单变为已确认 |
| 4 | 生产计划 | 选择该订单排产，计划数量 100，填写开始/结束日期 | 生成草稿计划 |
| 5 | 生产计划 | 点击“发布” | 计划变为已发布 |
| 6 | 生产工单 | 从该计划创建工单 | 生成待下发工单，数量/日期来自计划 |
| 7 | 生产工单 | 依次“下发 → 开始生产” | 工单变为生产中，计划和订单变为生产中 |
| 8 | 生产报工 | 选择生产中工单，填本次生产数量/合格/不合格 | 有效报工计入进度 |
| 9 | 生产工单 | 累计有效报工恰好 100 后点击“完成” | 工单、计划、订单同步完成 |
| 10 | 生产统计 | 选择日期/产品查看 | 核对产量、合格、报废和明细 |

### 5.1 数量口径

```text
单次生产数量 = 合格数量 + 报废数量
工单完成数   = 所有有效报工的（合格数量 + 报废数量）
工单剩余数   = max(工单计划数量 - 工单完成数, 0)
工单完成率   = min(工单完成数 / 工单计划数量, 100%)
```

计划、订单的合格数、报废数和完成数都从有效报工逐层汇总；报废计入“已处理数量”，但不计入合格产量。

### 5.2 状态流转

**生产订单**

```text
草稿 → 已确认 → 生产中 → 已完成
草稿/已确认 → 已取消
```

**生产计划**

```text
草稿 → 已发布 → 生产中 → 已完成
草稿/已发布 → 已取消（需满足取消条件）
```

**生产工单**

```text
待下发 → 已下发 → 生产中 ⇄ 已暂停
生产中 → 已完成
待下发 → 已取消（随计划取消）
```

已完成、已取消是终态，不能恢复，也不能继续报工。

## 6. 模块操作说明

### 6.1 产品管理

- 字段：产品编码、产品名称、规格型号、计量单位、备注、状态。
- 产品编码唯一，名称和单位必填。
- 产品停用后不能用于新订单，历史订单仍可正常查看。
- 系统不提供产品物理删除；已被订单引用的产品只能停用。
- 列表支持按编码/名称关键字和状态筛选。

### 6.2 生产订单

- 新建时填写订单编号、产品、订单数量、要求交期、备注。订单编号由业务人员填写且唯一；计划、工单、报工、质检编号由系统自动生成。
- 订单编号唯一；数量必须为正整数；交期不得早于当天。
- 只有启用状态的产品可以创建订单。
- 草稿订单可以编辑；编辑请求带版本时间，页面过期提交会被拒绝，需要刷新后重试。
- 确认后订单进入已确认状态，才能排产。
- 一个订单最多一份生产计划。
- 取消条件：不存在已发布/已执行计划，且没有有效报工。取消订单会同时取消其草稿计划和待下发工单。
- 订单详情展示关联计划、工单、有效报工、合格/报废/完成数量和进度。

### 6.3 生产计划

- 只显示已确认且尚未排产的订单。
- 计划数量必须等于订单数量。
- 计划结束日期不得早于开始日期，也不得晚于订单交期。
- 一个订单只能创建一份计划。
- 草稿状态可编辑；发布后关键数量和日期不可修改。
- 发布后，计划才能创建工单。
- 取消条件：工单尚未开始且没有有效报工；取消会取消待下发工单。
- 计划详情展示关联工单编号、状态、数量、合格/报废/完成数量和已完成工单数。

### 6.4 生产工单

- 工单只能从“已发布”计划创建，且一个计划只能创建一张。
- 工单数量、开始日期、结束日期由计划自动带出，前端不能修改。
- 操作顺序：

```text
下发 → 开始生产 →（可暂停/恢复）→ 完成
```

- 完成条件：所有有效报工的“合格 + 报废”必须**恰好等于**计划数量；不足或超出都不能完成。
- 完成后工单、计划、订单同步为已完成。
- 工单详情可查看关联报工记录、累计数量、剩余数和进度。
- 工单没有独立删除入口；计划取消时只取消待下发工单。

### 6.5 生产报工

- 只有“生产中”的工单可以报工。
- 报工日期默认为当天；生产数量必须等于合格数 + 不合格数，且大于 0。
- 累计报工量不能超过工单计划量，超报会返回业务冲突。
- 报工人由服务端根据登录身份确定，前端不能伪造报工人。
- 每次提交带唯一请求键，重复点击不会生成重复报工。
- 报工记录不允许编辑或物理删除。
- 作废规则：
  - 需要 `report:void` 权限；
  - 必须填写原因；
  - 只有工单仍在生产中才能作废；
  - 作废后记录保留，但不计入进度和统计；
  - 作废后可按正确数量重新报工。
- 操作员只能看到本人报工；主管及以上可查看全部报工。

### 6.6 质量管理

- 质检记录必须关联工单，可选关联某一条有效报工。
- 检验数量 = 合格数 + 不合格数。
- 工单累计检验数量不能超过该工单有效报工的合格数量。
- 存在不合格品时必须填写不合格原因。
- 处置状态：待处理、让步接收、返工、报废。
- 处置必须填写说明；已处置记录不能重复处置。
- 质检记录采用追加写入，不覆盖历史。

### 6.7 设备管理

- 设备档案字段：设备编号、名称、规格型号、位置、备注。
- 设备编号唯一，不提供物理删除。
- 常规状态：闲置、使用中、停用。
- 点击“报修”进入维修中状态；同一设备只能有一条未完成维修记录。
- 维修中不能修改设备档案或直接改状态。
- 点击“维修历史 → 完成维修”，填写处理说明后设备恢复为闲置。
- 设备状态为人工维护字段，不连接传感器或 PLC。

### 6.8 工作台与生产统计

**工作台**

- 默认查看近 30 日生产概况：生产订单数、生产中工单数、有效报工产量、质检不合格数。
- 支持按产品筛选，筛选后卡片同步刷新。
- 提供生产统计、产品、订单、计划、工单、报工、质量、设备、系统管理等快捷入口。

**生产统计**

- 日期范围必填，最长 366 天。
- 支持按产品、订单状态筛选。
- 展示内容：

| 区块 | 口径 |
| --- | --- |
| 订单数 | 统计期间创建的订单，按当前状态计数 |
| 工单数 | 统计期间创建的工单，按当前状态计数 |
| 有效报工产量 | 报工日期在期间内的有效报工，合格 + 报废 |
| 质检合格率 | 期间质检记录的合格数 / 检验数 |
| 质检不合格 | 期间质检记录的不合格数 |
| 每日生产数量 | 按报工日期汇总有效报工 |
| 工单状态 | 当前工单状态分布 |
| 计划执行情况 | 按计划当前状态统计计划量、有效报工量 |
| 产品生产排行 | 按产品汇总有效报工，最多前 10 |
| 报工明细 | 有效报工逐条明细，最多 500 条 |

- 作废报工不参与任何产量、进度和排行统计。
- 统计页面会明确显示当前日期范围和筛选条件。

### 6.9 系统管理

**用户与角色**

- 新增用户：登录账号、显示名称、初始密码（至少 12 位）、角色。
- 编辑用户：可修改显示名称、状态、角色；密码留空表示不修改。
- 停用用户后不能登录，历史数据保留。
- 不能停用最后一名启用管理员，也不能移除其 ADMIN 角色。

**角色与权限**

- 新增/编辑角色，按模块勾选权限。
- 权限保存为整体替换：取消勾选的权限会被移除。
- `ADMIN` 角色的“管理用户”“管理角色”权限在界面上禁用取消，防止系统失去管理入口。
- 角色权限变更后，已登录用户需要退出并重新登录，后端会话权限才会完全刷新。

**个人设置**

- 修改显示名称。
- 修改本人密码：需输入当前密码，新密码至少 12 位。
- 修改密码后当前会话继续有效，下次登录使用新密码。
- 系统不提供自助注册和邮件找回；忘记密码由管理员在用户编辑中重置。

## 7. 关键业务规则速查

| 规则 | 说明 |
| --- | --- |
| 单产品订单 | 一张订单只包含一个产品 |
| 一订单一计划 | 一个订单最多创建一份生产计划 |
| 一计划一工单 | 一份计划最多创建一张工单 |
| 计划量 = 订单量 | 计划数量必须与订单数量一致 |
| 工单量 = 计划量 | 工单数量、日期由计划决定 |
| 报工只限生产中 | 待下发、已暂停、已完成、已取消均不能报工 |
| 防超报 | 累计合格 + 报废不得超过计划量 |
| 完工必须恰好 | 有效报工总量必须恰好等于计划量 |
| 作废不删除 | 保留记录、作废人、时间和原因，但不计入统计 |
| 无物理删除 | 产品、订单、计划、工单、报工均不提供直接删除 |
| 服务端校验 | 数量、状态、权限、报工人均由后端校验 |
| 操作留痕 | 关键业务动作写入操作日志 |

## 8. 常见问题

**Q1：登录后看不到某个菜单？**

该账号的角色没有对应权限。让管理员在“系统管理 → 角色与权限”中授权，然后退出重新登录。

**Q2：新建订单时选不到产品？**

只有启用状态的产品可以用于新订单。先在产品管理中启用产品。

**Q3：排产时没有可选择的订单？**

订单必须是“已确认”状态，并且尚未创建生产计划。

**Q4：计划无法发布？**

只有草稿计划可以发布；发布后不可重复发布，也不能再修改数量和日期。

**Q5：计划无法创建工单？**

计划必须是“已发布”，关联订单仍然有效，并且该计划还没有工单。

**Q6：工单无法开始生产？**

工单必须先“下发”，再进行“开始生产”；状态顺序不能跳过。

**Q7：报工提交失败，提示超过计划数量？**

查看工单详情的累计完成数和剩余数，确认本次数量没有超过剩余量。已作废记录不计入累计。

**Q8：工单无法完成？**

有效报工的“合格 + 报废”必须恰好等于计划数量。数量不足需要继续报工；数量超出通常说明报工数据有误，需要授权人员作废后重新报工。

**Q9：报工无法作废？**

作废需要 `report:void` 权限，必须填写原因，且工单必须仍在生产中；已完成或已取消工单的报工不能作废。

**Q10：统计数字和预期不一致？**

依次检查日期范围、产品筛选、订单状态筛选；确认只统计有效报工；质检数量是独立指标，不与报工数量相加。

**Q11：管理员把自己停用了怎么办？**

系统会阻止停用最后一名启用管理员。若已发生异常，需要由数据库管理员在维护窗口恢复账号状态，并检查操作日志。

**Q12：忘记密码怎么办？**

系统没有自助找回。由管理员进入“系统管理 → 用户与角色”，编辑该用户并设置新密码。

## 9. 运维与安全建议

1. **先备份再升级**：数据库升级前做全量备份；已有库按 `V2` 到 `V7` 顺序执行增量 SQL，新库直接使用最新 `docs/sql/init.sql`。
2. **生产必须使用 HTTPS**：设置 `SESSION_COOKIE_SECURE=true`，避免会话 Cookie 在明文 HTTP 中传输。
3. **最小权限**：只给用户完成工作所需的角色；离职人员及时停用。
4. **管理员账号分离**：至少保留两名管理员，但不要共用账号。
5. **关注操作日志**：关键操作写入 `sys_operation_log`，排查问题时可结合响应中的 `traceId` 和 `X-Trace-Id`。
6. **健康检查**：`GET /api/health` 可用于负载均衡或监控探活。
7. **不要提交密钥**：`.env`、数据库密码、bootstrap 密码不得进入代码仓库或日志。
